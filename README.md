# Codex Local Bridge for Figma Desktop

A development plugin and authenticated local bridge that let a local Codex agent or command-line client edit the Figma Design file currently open on your computer.

The bridge accepts structured JSON operations for text, colors, positions, components, frames, dimensions, Auto Layout, and appearance copying. It never executes JavaScript, shell commands, or arbitrary property setters supplied in a request.

**Plugin version: 1.1.1. HTTP protocol revision: 1.1.0.** These numbers intentionally differ: automatic application was added without changing the HTTP protocol.

## Requirements

- **Figma Desktop** for Windows or macOS, with edit access to a Figma Design file. Development plugin installation requires the desktop application. See [Figma's development plugin guide](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development).
- **Node.js 20 or newer**, with npm. For a new installation, choose a currently supported LTS release from the [official Node.js download page](https://nodejs.org/en/download).
- The complete project folder on the **same computer** as Figma Desktop.

Check that Node.js and npm are available:

```powershell
node --version
npm --version
```

There are no third-party npm dependencies to install. The delivered `plugin/code.js` and `plugin/ui.html` are already built; you can install the plugin without running `npm install` or a build step.

The plugin interface and some supporting documents are currently in French. This README uses the exact French button labels alongside their English meanings.

## Quick start from a fresh Windows clone

Replace `YOUR_REPOSITORY_URL` with the repository's clone URL. Run these commands in PowerShell:

```powershell
git clone YOUR_REPOSITORY_URL figma-local-bridge
cd figma-local-bridge
npm.cmd run setup
npm.cmd start
```

`setup` checks Node.js and the project files, builds the plugin without downloading dependencies, creates an ignored `commands/` folder, and prints the **absolute manifest path for this clone**. Import that manifest into Figma Desktop, run the plugin, paste the PLUGIN key printed by the bridge, and click **Connecter**. Keep the bridge terminal open.

In a second terminal opened in the clone:

```powershell
npm.cmd run doctor
node client/cli.mjs send examples/01-selection.json
```

`doctor` checks the plugin files, authenticated local bridge, protocol revision, and connected Figma session without printing keys. It exits with code 0 when ready, 2 if the bridge works but Figma needs connecting, or 1 for a setup/connection error. The selection command is read-only.

On Windows, `npm.cmd` avoids PowerShell's possible `npm.ps1` execution-policy error; no execution-policy change is needed. On other shells, the same npm scripts work with `npm`.

### Configuration another agent needs

**There are no required environment variables to fill in.** `.env` files are ignored as a precaution; this application does not load them. The tracked [.env.example](.env.example) documents that explicitly. Copying it to `.env` is not required and has no runtime effect.

| Setting | How it is supplied |
| --- | --- |
| Bridge address and port | Fixed to `127.0.0.1:38475`; no `HOST` or `PORT` environment override |
| Agent authentication key | Generated by `npm start`, stored in ignored `.local/agent.json`, read automatically by the CLI |
| Plugin authentication key | Generated by `npm start`, printed once for the user to paste into the Figma plugin |
| Numeric Figma plugin ID, if requested by Figma | Supplied via `npm run configure -- YOUR_NUMERIC_PLUGIN_ID`, or `npm run setup -- --plugin-id YOUR_NUMERIC_PLUGIN_ID` |
| OpenAI/Figma API credentials | None required by this bridge |
| Windows username or personal paths | None to configure; scripts resolve their own project folder |

An agent can run setup and connection checks from any clone location, including paths with spaces. The Figma Desktop import and plugin-key pairing remain local UI steps; a Git clone alone does not connect to an open document. After pairing, the local agent uses `client/cli.mjs` and saves personal mutation files in the ignored `commands/` folder. Automatic mode applies those mutations immediately after validation, so start with the read-only selection example.

## 1. Install the development plugin

1. Extract the entire archive into a permanent folder named `figma-local-bridge`. Keep the folder after installation: Figma loads the plugin files from that location.
2. Open a Design file in **Figma Desktop**.
3. Open the Figma menu, then **Plugins → Development → Import plugin from manifest…**. Menu wording may vary slightly by Figma version or language.
4. Select **`plugin/manifest.json`** from this project.
5. Run **Codex Local Bridge** from the development plugins menu. Keep its window open while using the bridge.

### If Figma asks for a numeric plugin ID

The delivered manifest does not contain a private plugin ID. If your Figma installation requires one:

1. In Figma Desktop, select **Plugins → Development → New Plugin…**.
2. Create a Figma Design plugin using the **Custom UI** template. Save this temporary scaffold in a separate folder.
3. Open the scaffold's generated `manifest.json` in a text editor and copy the numeric string in its `id` field.
4. Open a terminal in the **bridge project folder**, the folder containing `package.json`.
5. Run the following command, replacing `YOUR_NUMERIC_PLUGIN_ID` with the ID assigned to you by Figma:

```powershell
npm run configure -- YOUR_NUMERIC_PLUGIN_ID
```

Import **this project's `plugin/manifest.json`** again, then run Codex Local Bridge. Do not import the temporary scaffold instead, and do not use another plugin's ID. Figma documents how IDs are assigned in the [plugin manifest reference](https://developers.figma.com/docs/plugins/manifest/).

The numeric plugin ID identifies the plugin; the connection key used below is generated separately by the bridge.

## 2. Start the local bridge

Open a terminal in the project folder containing `package.json`, then run:

```powershell
npm start
```

Keep this terminal running. The server listens only on **`127.0.0.1:38475`**. The plugin connects through **`http://localhost:38475`**, which is allowed for development in its manifest.

The terminal prints a line beginning with **`Clé PLUGIN à coller dans Figma`**, followed by a 64-character hexadecimal key. Copy the key only, without the surrounding text.

The bridge generates two different keys at every startup:

| Key | Where it is used |
| --- | --- |
| **Plugin key** | Printed in the server terminal; paste it into the Figma plugin |
| **Agent key** | Saved automatically in `.local/agent.json`; read by the local client without displaying it |

Do not paste the agent key into Figma or a chat. Do not commit or share `.local/agent.json`. No OpenAI API key or Figma API token is needed for this bridge.

## 3. Connect the plugin

1. In the plugin, paste the **plugin key** into **Clé plugin affichée par le pont**.
2. Click **Connecter** (Connect).
3. Check that the status shows **Connecté**, the current page ID, and a session ID.
4. Select a layer in Figma, then click **Actualiser les identifiants** (Refresh IDs). The page and selected layer IDs should appear.

The plugin is authorized for the page that was open when you connected. Changing pages disconnects it; reconnect to authorize the new page. Only one plugin session can use the bridge at a time.

## 4. Verify the connection from a second terminal

Leave the server terminal open. Open a **second terminal** in the same project folder and run:

```powershell
node client/cli.mjs capabilities
node client/cli.mjs session
node client/cli.mjs send examples/01-selection.json
```

Expected results:

- `capabilities` reports `protocolRevision: "1.1.0"` and 14 supported operations.
- `session` reports an active session with the same protocol revision. A `null` session means you still need to connect the plugin.
- The selection command returns the IDs and properties of the selected layers. It does not change the document.

The client prints a `commandId` before sending each command, then waits for its result. Keep that ID if the request or response fails.

## 5. Send a design change

1. Read the selection or navigate the layer tree to obtain real node IDs.
2. Create a local `commands/` folder, copy an example there (for example `commands/change-text.json`), and replace its placeholder IDs, text, and dimensions with the values you actually intend to use. This folder is ignored by Git so personal design commands stay local.
3. Send the edited file from the project folder. For example, after adapting the text example:

```powershell
node client/cli.mjs send commands/change-text.json
```

All example IDs such as `123:456` are fictitious. Example dimensions, including the height `320`, are illustrative and must be chosen after inspecting the real content.

The client expects a JSON file containing an `operations` array. It obtains the session and page IDs automatically and generates a new command ID. For example:

```json
{
  "operations": [
    { "type": "setText", "nodeId": "123:456", "text": "Continue" }
  ]
}
```

### Automatic and manual application

**Automatic mode is enabled by default** in plugin version 1.1.1. The checkbox **Appliquer automatiquement les modifications** means “Apply changes automatically.” New mutation batches are validated and applied as soon as they arrive, without a separate click for each batch.

Wait for the command result, then inspect the design or read the affected nodes again. The plugin displays recent results and the last received modification. Use **Undo in Figma** to revert a change after checking it.

To review future changes before applying them, uncheck that checkbox. In manual mode, each new mutation batch waits for **Appliquer** (Apply) or **Refuser** (Reject).

- A batch that has already started continues using its original mode.
- A batch already waiting for manual approval is not approved retroactively when you enable automatic mode.
- The mode choice stays in memory for the current plugin run. A fresh plugin run starts in automatic mode.
- Read-only commands always run automatically.

Automatic mode keeps the same authentication, page, lock, font, schema, expiration, and duplicate-command checks. It does not add new operations or permit arbitrary code.

### Inspect a command's status

Replace `COMMAND_ID` with the ID printed by the client:

```powershell
node client/cli.mjs status COMMAND_ID
```

Commands expire after two minutes. **Ctrl+C in the client terminal stops waiting; it does not cancel a command already submitted.** In manual mode, reject a pending command inside the plugin.

If a result is `unknown`, the command may already have changed the document. Inspect Figma before sending another command for the same intent. For `failed`, inspect the error, `failedIndex`, `appliedCount`, and any partial results. A batch is not an atomic transaction: earlier operations may have succeeded.

## Example commands

| File in `examples/` | Purpose |
| --- | --- |
| `01-selection.json` | Read the selection and layer IDs |
| `02-text.json` | Replace an existing text layer's contents |
| `03-color-position.json` | Set a solid fill and move a freely positioned layer |
| `04-create-component.json` | Convert an existing layer into a component |
| `05-create-instance.json` | Create an instance of a component on the authorized page |
| `06-instance-properties.json` | Change existing TEXT, BOOLEAN, or VARIANT instance properties |
| `07-inspect-nodes.json` | Read known nodes and exact instance property names |
| `08-children.json` | Read up to 10 direct children; use `nextCursor` to continue |
| `09-inspect-layout.json` | Inspect structure, geometry, Auto Layout, and appearance |
| `10-equal-heights.json` | Set two ordinary frames to the same measured fixed height |
| `11-create-row.json` | Create a horizontal row inside a compatible Auto Layout parent |
| `12-create-placeholder-text.json` | Create editable text using a local text layer's typography |
| `13-copy-appearance.json` | Copy supported appearance properties without copying contents or children |

Create parents first and wait for their returned IDs before sending commands to create their children. Likewise, use the returned `componentId` before creating an instance, then use its `instanceId` to inspect or edit it. Instance property names must exactly match `componentProperties`, including any `#…` suffixes.

For detailed inspection, `getNodes` accepts `details: ["structure", "geometry", "layout", "appearance", "text"]`, with at most five node IDs. Mixed, unavailable, and truncated properties are marked explicitly. For complete schemas and restrictions, see [docs/PROTOCOL.md](docs/PROTOCOL.md), currently in French.

## Using a local Codex agent or browser ChatGPT

A **Codex agent running locally on the same computer** can write command files and run `node client/cli.mjs send path/to/command.json`, subject to its local permissions. This project provides a CLI and HTTP API; it does not include an MCP server.

A useful instruction for a local agent is:

> Use the local bridge client to read the Figma session and selection. Obtain real node IDs before editing. Send only supported JSON operations, wait for each result, and read the affected nodes again to verify the change. Automatic mode is enabled in the plugin. Never replay an uncertain command without inspecting its effects first.

**ChatGPT in a browser does not directly connect to processes on your computer's localhost through this project.** It can help prepare the JSON, which you can save and send with the local client. An agent running on a different computer or in the cloud also cannot reach this local bridge directly. Do not expose it through a public tunnel or proxy.

## Stop, restart, or update

- **Stop the bridge:** press Ctrl+C in the terminal running `npm start`.
- **Disconnect Figma:** click **Déconnecter** (Disconnect). Closing the plugin also stops its polling; the server expires its session after 30 seconds without plugin requests.
- **Restart the bridge:** run `npm start` again and reconnect using the **new plugin key**. Both keys change, and the in-memory command history is cleared.
- **Update from 1.0.x:** update both bridge and plugin files, restart the bridge, reload the plugin, and reconnect. Check the capabilities and session protocol revisions.
- **Update from 1.1.0 to 1.1.1:** the HTTP protocol remains 1.1.0, so this update alone does not require restarting an already compatible bridge. Reload the plugin and reconnect if needed. If an old session is still registered, disconnect it or wait 30 seconds after closing the old plugin.

Keep your assigned manifest ID, private credentials, and personal command files when updating. Inspect any uncertain previous commands before a restart clears their history. The automatic checkbox controls **design changes**, not software updates: replacing project files and restarting/reloading them remain separate steps.

## Important operating limits

- Access is restricted to the authorized current page. Node IDs are explicit; selecting a different layer does not retarget an existing mutation command.
- Locked nodes and locked ancestors are rejected. New structural operations require ordinary layers outside components and instances, with PAGE or FRAME parents for creation.
- `resizeNode` does not scale children or rewrite text. Auto Layout can still recalculate positions and parent sizes. HUG/FILL dimensions must be handled explicitly before setting a fixed size.
- `setFill` replaces all existing fills with one solid paint. Use `copyAppearance` to reuse supported gradients, styles, and variable references. Unsupported mixed styles, patterns, and style overrides are rejected rather than approximated.
- Requests are limited to 64 KiB and batches to 20 operations. Child navigation is paginated at 10 nodes. Results are capped at 12,000 JSON string units; request fewer nodes or detail groups if a result is too large.
- The queue and history exist only in memory: at most 32 active commands and 2,048 command IDs per server run. There is no automatic replay and no exactly-once guarantee across restarts.
- The bridge uses two independent authentication keys and listens only on IPv4 loopback. Protect `.local/agent.json`; keep the project in a private account folder. See [SECURITY.md](SECURITY.md) for the full model and Windows file permission considerations.

Before publishing, keep credentials in the ignored `.local/` or `.env` files, personal command files in `commands/`, and private captures in `screenshots/` or `recordings/`. The personal `docs/PORTFOLIO.md` workflow is also ignored and excluded from the public archive. `.gitignore` prevents matching untracked files from being added normally; it does not remove files already tracked or detect secrets pasted into source code or allowed documentation. Review staged changes before committing. Do not force-add private files.

The plugin must stay open in a modifiable Figma Design file. It edits that open document through the Plugin API; it does not edit a `.fig` file directly on disk. Figma may continue syncing the document normally.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `node` or `npm` is not recognized | Install Node.js, reopen the terminal, and check the version commands |
| `package.json` cannot be found | Open the terminal in the extracted project root, not its parent folder or `plugin/` |
| Figma requests a plugin ID | Follow the numeric ID instructions above using an ID generated by Figma |
| `EADDRINUSE` | Another process is using port 38475; stop the identified previous bridge before starting another |
| `Failed to fetch` or a CSP error | Keep the bridge running on the same computer; use Figma Desktop and a development import; check localhost access and the manifest's development domain |
| HTTP 401 | Reconnect with the plugin key from the current bridge run; the CLI reads the current agent key automatically |
| Another session already exists | Disconnect the other plugin, or wait 30 seconds after closing it |
| Page changed / node outside the page | Reconnect on the intended page and read the IDs again |
| The UI stays on `Chargement…` (Loading) | Verify that you launched the updated plugin from the correct folder; close/reopen it and check for **Interface 1.1.1** |
| Old plugin / unknown `protocolRevision` / missing capabilities route | Update and restart the bridge, then reload and reconnect the plugin; the expected protocol revision is 1.1.0 |
| Missing font | Make the font available in Figma before sending a new command |
| HTTP 429 or history full | Wait for the rate window; if the ID history is full, inspect outstanding results before restarting |
| `unknown` or a partial failure | Inspect the document and returned results before sending another command |

Do not solve a local connectivity issue by exposing the bridge publicly or disabling global security protections.

## Development and project layout

After editing files in `src/`, rebuild the installable plugin:

```powershell
npm run build
npm run check
npm test
```

`build` generates `plugin/code.js` and copies the UI. It preserves `plugin/manifest.json` and any assigned plugin ID. `check` verifies that the generated files match the sources. Tests use a simulated Figma API and real local HTTP transport; check [VALIDATION.md](VALIDATION.md) for their scope. A real-document check is still needed for design mutations in your Figma environment.

```text
plugin/       Installable manifest, generated plugin code, and UI
src/          Shared validator, Figma engine, connection handling, and UI source
bridge/       Local HTTP server using Node.js built-in modules
client/       Command-line client for local agents and terminal use
examples/     Thirteen JSON examples to adapt
scripts/      Setup, connection diagnostics, build, and numeric plugin ID configuration
test/         Protocol, engine, bridge, and UI tests
docs/         Protocol reference, manual checks, and portfolio workflow
```

Additional documentation is currently in French: [protocol reference](docs/PROTOCOL.md) and [manual acceptance checks](docs/ACCEPTANCE.md). A personal portfolio workflow may be kept locally as `docs/PORTFOLIO.md`; it is not part of the public repository or archive.
